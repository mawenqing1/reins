# Reins 驭码

**AI Agent 任务协作平台** —— 你的 AI 同事，已经到岗。

像给同事派活一样给 AI Agent 派任务：写代码、做调研、整资料、写文案、处理工单——把活儿说清楚，派出去，进度、过程、结果都在你眼前，验收你说了算。

**这是能真跑的版本**：Agent 可配置为「真实 API」模式（OpenAI 兼容协议，支持智谱 GLM / DeepSeek / Kimi / 通义 / OpenAI / 自定义），流式执行、真实 token 计量、打回带反馈重跑；也内置零配置的「演示引擎」（本地模拟）。

## 快速开始

```bash
cd xfw/reins
npm install        # 首次（已装好可跳过）
npm start          # 编译 LESS → 启动桌面客户端
```

**开启真实执行**：控制台 → 设置 → 模型与密钥 → 「GLM · 去配置」→ 填入你的 API Key → 测试连接 → 保存。之后把任何任务指派给该 Agent，即是真实调用（流式输出、真实 tokens）。

- 样式源码全部为 **LESS**（`src/*.less`），`npm start` 会先编译再启动；改样式用 `npm run watch:css` 监听增量编译
- 官网落地页：`web/index.html`（浏览器直接打开，或客户端菜单「帮助 → 产品官网落地页」）
- 控制台：客户端窗口本体；浏览器打开 `web/app.html` 为降级模式（localStorage + 仅演示引擎）
- 网络受限环境重装依赖时：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install`

## 说明

应用以**空白工作区**起步，不带任何演示数据：首次打开只有「我的团队 → 我的空间」和一个空看板，到 Agent 页接入真实服务后即可开始派活。内置的三个例程（站会报告 / AI 分诊 / 周报生成）为真实计算功能，基于你的实际任务数据生成。

## 飞书接入

两种通道，都在「集成 → 飞书」配置，密钥经系统钥匙串加密后落盘：

| 通道 | 能力 | 需要什么 |
|---|---|---|
| **自建应用** | 发卡片 + **读群指令**（双向同步） | App ID / App Secret / 群 `chat_id`，应用需开 `im:message`（发送）与 `im:message:readonly`（读取）权限并发布版本 |
| **群机器人** | 仅出站推送（最快见效，无需审核） | 自定义机器人 Webhook 地址；开了「加签」就再填密钥 |

- **推送事件**：任务创建 / 完成归档 / 验收打回 / 执行失败 / 执行超时（逐项开关）
- **报告推送**：站报、周报、每日摘要在「设置 → 自动化调度」里可指定推送去向（看板 / 飞书 / Webhook / 两者）
- **群指令**（需开启「读取群指令」）：`/reins status` 空间概况、`/reins list` 未完成任务、`/reins new 标题 | 描述` 建任务、`/reins help`
- **群内审批**：`/reins approve REINS-42` 验收归档、`/reins reject REINS-42 原因` 打回重做、`/reins revoke REINS-42` 撤回验收。与客户端按钮走同一条状态迁移路径（含流水线重置、时间线留痕）
  - 说明：飞书**卡片按钮回调**需要公网可访问地址（`card.action.trigger`），与客户端轮询的内网架构冲突，故审批用群指令承载同一语义
- 收消息用**轮询群历史消息**而非公网回调：桌面端在内网也能用，不需要内网穿透；按 `message_id` 去重、水位重叠 60s 防漏
- 协议细节、权限清单与排错见 [docs/飞书接入指南.md](docs/飞书接入指南.md)

## 真实执行的工作方式

1. 任务指派给 API 模式的 Agent 后，主进程直接调用你所选服务商（密钥只存本机 userData，不经任何第三方）
2. 执行过程流式回传：详情抽屉实时显示模型输出，可随时「终止执行」
3. 完成后交付物进入「待验收」：通过归档，或**打回重做**——Agent 会带着此前交付与你的反馈继续修改（多轮对话）
4. token 消耗按 API 返回真实累计；真实 API 模式的任务重启后不自动续跑（避免无感知计费），可手动重新启动

## 交付闭环（Git）

Agent 在隔离 worktree 里改完文件后，**改动只是工作区文件**——分支提交并未前进。直接推送会推出一个不含任何改动的空分支，而 `git push` 仍然返回成功。所以推送前必须先把改动落成提交：

1. 「提交并创建 PR」一键完成：`git add`（排除注入的 node_modules 链接）→ `commit`（提交信息 = 任务号 + 标题）→ `push --set-upstream` → 识别托管平台 → 建 PR
2. 推送前体检，两种常见误报都被拦下：
   - 有未提交改动 → 明确提示会丢失改动，建议走一键提交
   - 相对上游无新提交 → 提示「无需推送」，而不是假装成功
3. 作者信息缺失时用环境变量兜底（`GIT_AUTHOR_NAME=Reins`），不让非 git 用户撞上 `missing user.email`
4. 重复开 PR（422/400）会自动找回既有链接，不报错

## 成本与质量指标

- **Agent 卡片**：成功率（成功/失败按次数计，阈值着色）、平均耗时、累计花费
- **概览成本条**：累计花费 / 累计 tokens / 整体成功率 / 未定价执行次数
- **计价口径**：元 / 百万 tokens，输入输出分开算；`settings.modelPrices` 可覆盖内置参考价（设置 → 模型价格表）
- **不编造价格**：模型名与服务商都命中不了时返回「未定价」，该次执行只计 tokens 并单独计数，界面上注明「另有 N 次未计入」

## 数据层：大文本外置

状态档 `reins-data.json` 每次保存是全量序列化，而流水线各阶段产出与交付正文会一直留在内存态里（实测单个跑过多轮的流水线任务，其 `pipeline` 就占 69K）。

- 超过 **8KB** 的正文（阶段产出 / 交付正文 / 多轮对话 / 裁决依据）落盘到 `deliveries/text/<任务号>/`，state 里只留 `{__text, ref, bytes, preview}`
- 界面预览用 `preview`（前 400 字），不读盘也能显示；要全文时再异步取回并缓存
- 引用路径做白名单与穿越校验，越界读取直接拒绝；缓存键带字节数（同一任务重跑不会读到上一轮的旧正文）
- 写盘失败**保留原字符串**——数据不能因为优化而丢
- **导出备份会把正文内联回来**：备份是单个 .json，正文库目录不会跟着走，内联后换机导入才不丢交付内容
- 删除任务时同步清理其交付目录；设置页另有「回收孤儿文件」处理历史残留（导入旧档、手工删任务）
- **数据自检**：启动后静默体检一次（只在发现问题时提示），设置页可随时重扫——检查「引用是否都有对应文件」「孤儿目录」「磁盘占用」，正文缺失会精确指出是哪条任务的哪一段

实测同一份数据从 220K 降到 116K；剩余部分是本来就在阈值内的小文本与其它常规字段。

## 设计说明

- **产品形态**：桌面客户端 = 控制台 + 本地执行节点。已落地「本机节点在线」「Agent 接入检测」「独立工作区执行」「托盘常驻」等概念；真实执行走 OpenAI 兼容 API（见上节），如需接入本机 CLI Agent，可在主进程扩展子进程管理与 CDP。
- 任务/提示词/自动化等数据按**团队空间**隔离，空间可创建、切换、重命名、管理成员（管理员/成员/访客）与邀请；Agent 与密钥为本机全局配置，跨空间共享。
- 数据持久化：任务与空间数据存 `userData/reins-data.json`，客户端设置存 `userData/settings.json`；浏览器打开为降级模式（localStorage + 仅演示引擎）。
