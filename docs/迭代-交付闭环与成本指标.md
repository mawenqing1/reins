## 〇、先说结论：修掉了一个静默丢数据的缺陷

评估阶段用真实 git 仓库复现出一个**功能缺陷**，优先级高于其余所有功能项：

```
worktree 里有改动：  M a.txt   ?? b.txt
git log main..reins/K2  →  0 个提交
git push --set-upstream origin reins/K2  →  [new branch]，退出码 0
远程 reins/K2:a.txt     →  "base"        ← Agent 改的内容不在里面
远程 ls-tree reins/K2   →  只有 a.txt    ← 新建的 b.txt 根本没上去
```

原因链：Agent 在 worktree 里改的是**工作区文件**，`reins/<KEY>` 分支指向的提交从未前进；
`buildDelivery` / `applyDelivery` 只用 `git add -A -N`（意向添加，只用于生成 diff），从不 commit；
`pushBranch` 只判断 `r.status === 0`，于是「推出去一个空分支」被当成成功上报，任务卡显示 ✅。

README 里承诺的「推送分支 + 开 PR」在最后一环是空的，而 PR 因为分支无 diff 也是空的。

### 1.1 提交能力（`services/git-remote.js`）

新增三个函数：

| 函数 | 职责 |
|---|---|
| `uncommittedSummary(cwd)` | 盘点未提交改动（含未跟踪文件），排除 `node_modules`（worktree 里是注入的符号链接）与 `.reins-wt` |

### 1.2 推送前体检（`pushBranch`）

```

opts.commit=true 且 工作区脏  → 先提交，再推送
相对上游 0 个新提交           → { ok:false, kind:'no-commits' }
其它                         → 原有推送 + 错误分类
```

返回体新增 `commit`（提交信息/摘要）与 `ahead`，界面可直接展示。

## 二、P1 · 成本与质量指标

### 2.1 计价模块（`services/pricing.js`，纯函数）

- 单价查表优先级：**用户覆盖 > 内置模型价 > 服务商兜底 > 未定价（null）**
- `usage` 拆分兼容 OpenAI 与各家兼容协议（`prompt/completion_tokens`、`input/output_tokens`）；只有总量时按 3:1 估算并标记 `split:'assumed'`
- 金额单位统一「元 / 百万 tokens」，输入输出分开算；小额保留到 0.0001 元，避免 `¥0.00`
- **未知模型不编价格**：返回 `ok:false, cost:null, priced:false`，界面显示「未定价」并单独计数

### 2.2 Agent 指标

新增 `agent.stats = { fail, durMs, runs, unpriced }` 与 `agent.cost / priced`：

- 成功率 = 成功 / (成功 + 失败)，阈值着色（≥90% 绿 / ≥70% 琥珀 / 其余红）
- 平均耗时 = 累计耗时 / 样本数（`ms` / `s` / `m s` 自适应）
- 累计花费按模型单价累加；未定价的执行只计 tokens 并计 `unpriced`
- 概览页新增**成本与质量条**：累计花费 / tokens / 整体成功率 / 未定价次数

### 2.3 设置页价格表

「设置 → 模型价格表」：列出**在用模型 + 已覆盖 + 内置**三类，可增行、可清空某行（回落内置），保存写 `settings.modelPrices`。

### 2.4 顺带修掉的缺陷

`fmtDuration(ms, 0)` 用 `Math.max(1, samples)` 兜底，会把「没有样本」算成一个有意义的数字。改为样本 ≤ 0 直接返回 `null`。

### 2.5 测试

## 三、P1 · 数据层：大文本外置

### 3.1 问题定位（先量再改）

```
总大小 220K
  sp.tasks           204K
    单任务 pipeline  158K   ← 真正的大头
      stages          64K   ← 各阶段完整产出
    单任务 history    22K
    单任务 result     13K
```

流水线阶段产出与交付正文同源重复：磁盘 `deliveries/<KEY>/stages/sN/report.md` 已有一份，内存态又存一份，且每次 `save()` 全量序列化。

### 3.2 方案（`services/textstore.js`）

- 阈值 **8KB**（按 UTF-8 字节，中文 3 字节/字）：超过则落盘 `deliveries/text/<任务号>/<槽位>.md`，state 存 `{__text:true, ref, bytes, preview}`
- `preview` = 前 400 字：界面不读盘就能显示摘要
- 惰性全文：`textFull()` 按需取回并缓存；`textPending` 防并发重复读
- **写盘失败保留原字符串**——优化不能以丢数据为代价
- 路径安全：`safeRef` 白名单 + 拒绝穿越/绝对路径/非 `text/` 前缀；`resolveRef` 再做 `path.resolve` 前缀校验

### 3.3 接入范围

`task.result`、`pipeline.stages[].result`、`task.thread[].content`、`reworkCtx.qaReport/feedback`、`gate.evidence`。

渲染层所有渲染/导出路径统一走 `textOf()`（引用给 preview、字符串原样），需要全文的路径（流水线裁决、PR 描述、下载）走 `textFull()`。

### 3.4 实测效果

| 指标 | 改前 | 改后 |
|---|---|---|
| `reins-data.json` | 220K | **116K** |
| 最大流水线任务 `pipeline` | 69K | 引用化（正文 32K + 10K 落盘） |

实机验证：重载后引用态渲染无 `[object Object]`、摘要徽标正常、`textRead` 取回 19411 字符与磁盘文件一致、三类越权路径（穿越/绝对/越界）全部拒绝。

### 3.5 测试

`test/textstore.test.js` 新建，59 断言：阈值边界（含中文按字节）、写盘失败保留原文、预览语义、9 种非法 ref、`makeRef` 清洗后必然通过 `safeRef`（这条一开始是红的——`a..b` 会生成含 `..` 的路径）、真实读写往返、JSON 往返、主进程与渲染层接线。

## 四、P2 · 飞书群内审批

### 4.1 一次方案调整

原计划做「卡片内通过/打回按钮」。实现前确认：飞书卡片按钮回调走 `card.action.trigger`，**要求应用配置公网可访问的回调地址**——这与已定的「客户端轮询群消息、内网即用、无需穿透」架构直接冲突。

改为**群指令承载同一语义**：`/reins approve|reject|revoke <任务号> [原因]`，落在同一条拉取通道里，客户端下一轮同步时执行并回执卡片。

### 4.2 实现

- `parseCommand` 新增三类指令 + 中文别名（通过/验收、打回/驳回、待审/撤回）；任务号支持 `REINS-42` / `reins-42` / `42` 三种写法（`splitTaskArg` 归一）
- 渲染层 `handleFeishuCall` 执行，与客户端按钮**同一条状态迁移路径**：
  - `approve` → 校验必须待验收、拦住未裁决的代码变更 → `setStatus(done)` → 时间线 → `notifyHook` 推事件
  - `reject` → 反馈写入 `thread` 与 `comments`（标注来源飞书）→ 流水线重置 → 回 `todo` → 推打回事件
  - `revoke` → 待验收回到进行中
- 回执卡片按动作着色（绿/橙/灰），失败卡片带用法提示

## 七、复查轮：外置引入的三个回归（均已修复）

上一轮的大文本外置改动，在复查中发现三处**自己引入的**缺陷。它们的共同点是「功能看起来正常，但数据/结果已经不对」——比直接报错更危险。

### 7.1 导出备份不含外置正文（数据丢失风险）

外置后 state 里只有 `{__text, ref}`，正文在 `userData/deliveries/text/` 下；而备份是**单个 .json 文件**，不包含这个目录。

```
导出 → 备份里全是引用
换机导入 → text/ 目录没有跟着来 → 交付内容只剩 400 字摘要
```

用户会以为备份是完整的。修复：`exportData` 改为异步，先 `inlineAllText(state)` 把引用全部换成全文再序列化；单条正文取不到时保留 preview 并提示，不阻断导出。导入侧加 `liftTextRefs`，兼容「裸 state（含引用）」并把引用降级为摘要，避免留下指向不存在文件的引用。

### 7.2 孤儿文件回收误删正文库（实测真的发生了）

设置页「回收孤儿文件」初版实现里，`sweep(base, false)` 把 `deliveries/text` 当成一个普通任务目录——它不在 keep 清单里，于是**整个正文库被删**，6 个正文文件全灭。

修复：显式跳过容器目录，只对 `text/` 的子目录按 keep 判定。恢复过程：正文还留在内存缓存里，配合 `textRead` 校验后从备份精确写回（新增 `text:write` IPC 支撑这类恢复）。

顺带补上：删除任务时同步 `deliveryPurge` 清理 `deliveries/<KEY>/` 与 `deliveries/text/<KEY>/`（此前只有 state 变干净，磁盘永久残留）。

### 7.3 正文缓存永不失效（同任务重跑读到旧内容）

`textCache` 只用 `ref` 做键。同一任务重跑时阶段 id 不变（`stage-s1`），ref 也就没变，但正文已经换了——于是 `textFull` 一直返回上一轮的旧正文。

修复：缓存键改为 `ref + bytes`（引用对象里记录了写入时的字节数，正文一变自然失效），并加 50 条上限防长会话吃内存。

### 7.4 下载交付只给摘要

`downloadDelivery` 用的是 `textOf`（引用 → preview），外置的交付下载下来只有 400 字。用户拿到一个「看起来正常、其实残缺」的文件比报错更糟。

修复：改为 `await textFull()` 取全文；取不到时才退回摘要，并明确提示「正文缺失，已下载摘要」。

### 复查轮测试

`test/textstore.test.js` 96 → 100 断言，新增覆盖：
- 导出必须内联（含遍历四类字段、并发等待、快照而非原 state）
- 导入兼容两种形态
- **GC 不得误删 text/ 容器**（显式断言跳过逻辑，防止回退）
- 删除任务触发 purge、保留清单覆盖全部组织
- 缓存键必须带 bytes
- 下载走全文且缺失时降级提示

全量回归：**14 个文件 / 587 断言全绿**（复查轮前 546）。

## 八、复查轮 2：数据自检

前两轮暴露的静默数据问题（导出丢正文、GC 误删正文库、缓存读到旧内容）都有同一个特征：**不报错，只是结果不对**。加一层常驻体检，把这类问题从「用户某天发现」提前到「启动时就提示」。

### 8.1 纯函数层（`services/integrity.js`）

| 函数 | 职责 |
|---|---|
| `collectRefs(state)` | 扫出全部 `__text` 引用，附带可读位置（如「REINS-126 · UI 设计」），覆盖交付正文 / 多轮对话 / 阶段产出 / 测试报告 / 返工意见 / 裁决依据 |
| `verifyRefs(refs, exists)` | 逐个校验存在性，返回缺失清单与总体积；`exists` 由宿主注入（真实环境做路径安全解析 + `fs.statSync`），单测可完全离线 |
| `findOrphans(dirNames, keepKeys)` | 孤儿目录判定；**`text` 容器永不算孤儿**（上一轮就是踩了这个坑） |
| `buildReport(...)` | 组装三级结论：缺失（error）/ 孤儿（info）/ 体积（warn） |

体检逻辑刻意不碰磁盘、不碰网络——文件存在性从外面注入，所以能整段单测，也能在裸 Node 里跑。

### 8.2 主进程

`reins:integrity:check` 做真实扫盘：只读加载 state（不解密密钥）→ 收集引用 → 逐个 `statSync` → 扫 `deliveries/` 顶层目录 → 统计孤儿体积与正文库体积。

- 结果缓存 30 秒：设置页反复打开不重复扫盘；`force=true` 强制重扫
- 保存 / 删除任务 / 回收后自动失效缓存

### 8.3 界面

- **启动自检**：页面就绪 2.5 秒后静默跑一次，**只有发现「正文缺失」才弹提示**（孤儿、体积这类不打扰）
- **设置 → 数据自检**：健康时一行绿字（含引用数、占用、上次检查时间）；有问题时按类型分节列出，缺失项显示「任务号 · 位置 + ref」，孤儿项给一键回收按钮，底部常驻「重新检查」与「导出备份（含正文）」

### 8.4 实测

| 场景 | 结果 |
|---|---|
| 真实数据（6 处引用） | `healthy: true`，0.10MB，无告警 |
| 注入一个不存在的 ref | `healthy: false`，精确指出「REINS-IG1 · 交付正文」，error 级告警 |
| 造一个孤儿目录 | 识别为孤儿、面板出现「回收这 1 个目录」，回收后目录消失且 **`text/` 完好** |
| 页面重载 | 零控制台报错 |

### 8.5 测试

`test/integrity.test.js` 新建，58 断言：四类外置位置收集、畸形/空值不误判、`exists` 抛错按缺失处理、`text` 容器不判孤儿、四类结论组装、单行摘要、主进程与渲染层接线。

顺带修掉一个健壮性缺口：`collectRefs` 遇到 `null` 任务项会崩（state 被手工改坏就会这样），现已跳过非对象项。

全量回归：**15 个文件 / 645 断言全绿**（复查轮 1 为 587）。
