## 一、设计原则

1. **延续浅色控制台体系**：中性两阶底（纸面 `#f6f7f8` + 白卡 `#ffffff`）+ 白卡浮层；品牌墨青只出现在操作与选中态，不做大面积铺色。
2. **语义色三分，不引入新色相**：
   - 品牌青（`#12908a/#0e7a70`）＝ 可操作 / 正常动作 / 链接；
   - 琥珀（进行中 `#c47f17` 同源）＝ 进行中 / 瞬态重试 / 警示；
   - 红（`.bug` 系）＝ 失败 / 危险操作。
3. **状态可见性**：长时操作（重试、调度、流水线阶段）必须有颜色之外的第二通道（图标 ✕/▶/✓/○ 或文字标注），不只靠颜色区分。
4. **组件复用优先**：新增界面一律使用既有组件（`.set-row`、`.f-row`/`.f-2col`、`.status-pill`、`.switch`、`btn-o/btn-p/btn-danger`、modal 三段式），不再发明平行组件。

## 三、逐界面方案

### 3.1 执行终端 · 重试提示（任务卡 1）

- **位置**：任务详情抽屉流式日志区（`.term-scroll`），独立日志行，插在触发重试的失败输出之后。
- **组件**：`.ln.retry`，等宽字体 12px、行高 1.95（与终端一致），前置 `↻` 符号随事件文本带入（`↻ 重试中（第 N/M 次）…`）。
- **色彩**：`@warn-ink`。与 `.ln.err`（红 `#c05656`）、`.ln.act`（品牌青文字）构成三分：重试中＝琥珀、最终失败＝红、正常动作＝青。
- **边界**：重试耗尽后由 error 事件接管，日志切 `.ln.err`——颜色跃迁本身就是「从缓冲到定论」的信号。

### 3.2 设置页 · 执行引擎区块（任务卡 1）

- **布局**：`.set-row` 整行展开（`display:block`），内部两组 `.f-2col`：第一组「无响应超时 / 重试上限」，第二组「temperature / max_tokens / top_p」（第三项自然落到第二行左位，宽度对半不留孤列）。
- **输入**：数字输入纳入 `.f-row` 表单样式——padding 9×12、圆角 7px、`--line-strong` 描边、focus 品牌青描边 + 3px 光晕（`rgba(14,122,112,.13)`）。⚠ 本阶段修正：此前 8 个 number 输入为浏览器默认外观。
- **文案**：`.set-desc` 12px 灰阶；退避策略说明（1s→2s→4s→8s、Retry-After、仅 API 通路）固定在参数组下方。
- **动作**：`btn-p btn-sm`「保存执行策略」，区块内右下。

### 3.3 设置页 · 自动化调度（任务卡 2）

**列表行 `.sched-row`**：
- 结构：主信息列（`sr-main` 弹性伸展）＋ 操作组（立即运行 / 编辑 / 删除，`btn-o btn-sm`，删除加 `btn-danger-o`）＋ `.switch` 启停开关；行间虚线分隔。
- 主行：名称 13px/600 ＋ 类型标签 `.sr-tag`（站报/周报，中性灰——不用 `mode-pill`，那是 API/SIM/CLI 执行引擎语义）。
- 副行：`.set-desc` 频率文案 ＋「下次 M月D日 HH:MM」（今天则「今天 HH:MM」）＋ 可选「推送 Webhook / 上次运行 …」。
- **暂停态**（本阶段补强）：行级 `.off` → `sr-main` opacity .55 退隐；名称旁「已暂停」灰标签；副行以「暂停中（不触发）」替换「下次 …」——暂停时 `nextRun` 是过时值，照常显示会误导。开关之外提供第二视觉通道。

**弹窗**：标准 modal 三段式（520px）：`f-2col` 依次为 名称/类型、频率/时间（HH:MM）、星期/cron；Webhook 用 `f-check`；频率切换按需显隐星期与 cron 字段（隐藏行仍可取值交主进程校验）；底部说明「cron 为 5 字段标准表达式」。

### 3.4 设置页 · 安全存储（任务卡 3）

- **状态行**：`.status-pill idle`（绿「系统加密已启用」）/ `.status-pill offline`（灰「加密后端不可用」）＋ `.set-desc` 后端说明（Keychain / DPAPI / libsecret）。
- **盘点行**：`.set-desc`——已加密 N · 明文 N · 解锁失败 N（红字加粗）· 存储策略。
- **警示横幅 `.sec-warn`**：琥珀族三令牌，11×14 内边距、圆角 `@r-xs`；`<b>` 标题「⚠ 安全警示」＋ 说明 ＋ `btn-o btn-sm` 降级确认键。横幅仅在「加密不可用且存在明文」时出现，避免警示疲劳。
- **降级确认弹窗**：标准 modal，确认键 `btn-danger`（危险语义唯一入口）。
- **恢复加密**：行内 `.lnk` 文字链接（品牌青），不占按钮位。

### 3.5 设置页 · Git 远程（任务卡 5）

- 双令牌 `.f-2col` 密码框（GitHub/Gitee PAT）；任一令牌解锁失败时字段上方插入红字 `.set-desc` 警示（留空保存可保留密文）。
- 保存 `btn-p btn-sm`；说明文案固定在字段组上方（PAT 权限要求）。

### 3.6 新建任务 · 高级选项（任务卡 1）

- `details.adv-opts` 折叠容器：虚线 `--line-strong` 描边、圆角 `@r-xs`；summary 12.5px 灰、hover 加深至 `--ink`（本阶段补），原生三角标记指示开合。
- 展开后 `.f-2col` 三参数输入；**placeholder 显示全局默认值**——「留空＝继承全局」的心智由占位文本承载，不额外加说明行；组下 `.set-desc` 一行兜底（仅本次生效 / 坏值回退）。

### 3.7 任务抽屉 · 流水线面板（任务卡 4）

- **阶段清单 `.pp-stage`**：图标位 18px 等宽居中——`✓` 完成 / `↩` 返工 / `✕` 失败 / `▶` 当前 / `○` 待运行；主行阶段名 12.5px/600，副行角色名＋状态标注（「· 失败（可从断点重试）」「· 返工」「· 第 N 次执行」）。
  - 当前：`@warn-bg` 整行底、图标 `--doing`；完成：图标绿；**失败（本迭代新增态）：`@fail-bg` 整行底 + `@fail-ink` 图标与副行文字**。
- **甘特 `.pp-gantt`**（并行关系可视化，简化版）：
  - 容器：虚线 `--line` 描边、圆角 8px、10×12 内边距；
  - 波次行：`pw-idx`（W1/W2… 等宽 10.5px 灰）＋ 同波次胶囊左对齐并列（flex wrap），波次间上下衔接——「左右并列＝并行，上下相邻＝依赖」由 `pw-hint` 一行点破；
  - 胶囊 `.pw-stage`：99px 圆角、11.5px、3×10 内边距，四态：灰待运行（`#f4f4f2`/`--ink-dim`）/ 绿完成 / 琥珀进行中·返工 / 红失败（`@fail-*`）；
  - **运行中动效**：`pw-breathe` 1.8s 呼吸光环（`rgba(196,127,23,.16)` 扩散），与 `.pdot.running` 光环、状态点 pulse 同动效语言——柔和呼吸而非闪烁（本阶段补）；
  - 悬停 title 显示依赖（「依赖：X、Y」/「无依赖（并行根）」）。
- **裁决门 `.pp-gate`**：pass＝绿底 / rework＝琥珀底 + 打回目标与依据摘要（`.pp-evid` 11px 半透明）。
- **并行阶段终端**：每阶段独立 `run-box`（run-head 阶段名＋角色、进度条、流式日志），取消为 `btn-o`「■ 终止执行」。

### 3.8 任务抽屉 · 远程交付（任务卡 5）

- 操作行：`⇧ 推送 reins/<KEY>`、`⇄ 创建 PR` 两个 `btn-o btn-sm` ＋ 既有 PR 链接（`.pr-link` 等宽品牌青、外链 ↗）。
- 输出 `.git-log`：等宽 11.5px / 行高 1.8，`ln ok/act/err` 三色与执行终端完全一致（同一语法：`▸ 进行中 / ✓ 成功 / ✗ 失败`）；空时隐藏。
- PR 弹窗：标准 modal，head/base/标题/描述四字段 + 只读源分支；说明「令牌从设置读取」。

## 五、可访问性

- 文字对比度：`@warn-ink` 对 `#f7f8f9` / `@warn-bg` ≥4.5:1（AA）；`@fail-ink` 对 `@fail-bg` ≈4.6:1；修正前的 `#d29a3f`（~2.5:1）已淘汰。
- 全部状态伴随图标或文字标注，色弱可辨。
- 焦点样式沿用全局 `:focus-visible`（2px 品牌青外环）与表单 focus 光晕；数字输入纳入后同样获得。
