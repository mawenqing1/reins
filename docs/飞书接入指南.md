# Reins × 飞书接入指南

Reins 接入飞书分两条通道，都在客户端 **集成 → 飞书** 配置：

| 通道 | 能做什么 | 门槛 |
|---|---|---|
| **自建应用** | 发卡片 + 读取群指令（双向同步） | 企业管理员在开放平台建应用、开权限、发布版本 |
| **群机器人** | 仅出站推送 | 群里加一个自定义机器人，复制 Webhook 地址 |

> 两条都配时**应用优先**：应用能发群消息也能读群，机器人作为未配置应用时的兜底。

---

## 一、5 分钟跑通出站推送（群机器人，最快）

1. 飞书群 → 右上角 `…` → **设置** → **群机器人** → **添加机器人** → **自定义机器人**
2. 复制 Webhook 地址（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`）
3. 如开启了 **签名校验**，把密钥一并复制（Reins 会自动加签；加签失败会自动退回不带签名再试一次）
4. Reins → **集成 → 飞书** → 填「群机器人」下方的 Webhook 地址与加签密钥 → 勾选 **启用飞书推送**
5. 点 **发送测试卡片**，群里收到卡片即通

## 二、接自建应用（支持群指令双向同步）

### 1. 建应用

飞书开放平台 <https://open.feishu.cn/app> → **创建企业自建应用** → 记下 **App ID** 与 **App Secret**（凭证与基础信息页）。

### 2. 开权限

「权限管理」里开通并**发布版本**（权限不发布不生效）：

| 权限 | 用途 |
|---|---|
| `im:message`（以应用身份发消息） | 发卡片 |
| `im:message:readonly`（获取群组中所有消息） | 拉群历史消息、读群指令 |
| `im:chat:readonly`（可选） | 排查 `chat_id` 是否正确 |

### 3. 把机器人拉进群

应用详情 → 「应用能力」添加 **机器人**；然后在目标群里 **设置 → 群机器人 → 添加机器人 → 选择你的应用**。

### 4. 拿 `chat_id`

群 `chat_id` 形如 `oc_xxxxxxxx`。取法三选一：

- 群设置 → 群机器人 → 你的机器人 → 查看「群 ID」
- 用飞书 API 助手/调试台调 `GET /open-apis/im/v1/chats?page_size=20`（应用要有 `im:chat:readonly`）
- 群里 @机器人 发一句 `/reins help`，Reins 集成页「立即同步群消息」的报错里会带上服务端提示

### 5. 在 Reins 里填

集成 → 飞书 →

- **App ID** / **App Secret**
- **群 chat_id**
- 勾选 **启用飞书推送**
- 需要群里派活时再勾 **读取群指令**，同步间隔默认 45 秒（15s–10min）

保存后点 **发送测试卡片** 验证。

## 三、推送什么

| 事件 | 触发点 | 开关 |
|---|---|---|
| 任务创建 | 新建任务 / 流水线拆解 | `events.create` |
| 完成归档 | 验收通过 | `events.done` |
| 验收打回 | 打回重做（带打回原因） | `events.reject` |
| 执行失败 | Agent 执行报错（带错误摘要） | `events.fail` |
| 执行超时 | 报错信息命中「超时/timeout」 | `events.fail` |

报告类（站报 / 周报 / 每日摘要）走 **设置 → 自动化调度**，每个调度单独选推送去向：

- `只写看板`、`飞书`、`Webhook`、`飞书 + Webhook`
- 旧档的「推送到 Webhook」勾选会自动映射为 `Webhook` 去向，不需要手动迁移

同一任务同一事件 30 秒内只发一次（防抖），推送串行排队（飞书机器人有频控）。

## 四、群里怎么用

开启「读取群指令」后，在群里发（`@机器人` 前缀或 `/reins` 前缀都行）：

| 指令 | 作用 |
|---|---|
| `/reins status` | 空间概况：进行中 / 待处理 / 待验收 / 今日归档 + 最近归档 |
| `/reins list` | 未完成任务清单（按优先级排序，最多 15 条） |
| `/reins new 登录改版 \| 加验证码和错误提示` | 建任务：`\|` 或换行前是标题，后面是描述 |
| `/reins approve REINS-42` | **验收通过并归档**（仅待验收任务；有未裁决的代码变更时会拦下） |
| `/reins reject REINS-42 第二部分缺少来源` | **打回重做**，原因写进任务反馈与时间线；流水线任务会一并重置 |
| `/reins revoke REINS-42` | 撤回验收，回到进行中 |
| `/reins help` | 帮助卡片 |

任务号可简写：`/reins approve 42` 等价于 `REINS-42`；`reins-42` 也认。中文别名：`通过 / 验收`、`打回 / 驳回`、`待审 / 撤回`。

> **为什么审批用指令而不是卡片按钮？**
> 飞书的卡片按钮点击（`card.action.trigger`）要求应用配置**公网可访问的回调地址**，与本项目的「客户端轮询群消息」架构（内网即用、无需穿透）冲突。审批动作因此落在同一条拉取通道上：群里发一句指令，客户端下一轮同步时执行并回执卡片。语义与在客户端点按钮完全一致。

说明：

- 只处理**人发的**文本消息，机器人自己发的卡片、系统消息都会跳过
- 按 `message_id` 去重；每次拉取水位重叠 60 秒，避免边界漏消息
- 群指令建的任务会带 `飞书` 标签和时间线留痕，**不会**再反向推一张「任务创建」卡片回去（避免群里自说自话）
- 指令执行依赖控制台窗口在线（任务状态在渲染层内存里）；窗口未就绪时群里会收到「Reins 控制台未就绪」提示

## 五、安全

- `App Secret` 与机器人 `加签密钥` 属于密钥：落盘前经 **系统钥匙串**（macOS Keychain / Windows DPAPI / Linux libsecret）加密，磁盘上只有密文
- 系统钥匙串变更导致解不开时：显示「已加密 · 本机解锁失败」，**留空保存保留密文**，重新填写才覆盖，不会静默清空
- 所有请求由主进程发出（不受渲染层 CORS 限制），不经过任何第三方中转

## 六、排错

| 现象 | 原因与处理 |
|---|---|
| `获取 tenant_access_token 失败：invalid param` | App ID / Secret 填错，或应用未创建 |
| `invalid param: incoming webhook access token invalid` | 机器人 Webhook 地址不对（被截断/换了机器人） |
| `发送群消息 失败：...230002...` | 机器人不在该群，或 `chat_id` 不是这个群 |
| `...99991...` / 权限相关 | 权限没开或**开了没发布版本** |
| 同步状态一直「未开启」 | 需要同时满足：启用推送 + 读取群指令 + App ID/Secret/chat_id 齐全 |
| 群里发指令没反应 | 看集成页「最近错误」；确认应用有 `im:message:readonly`；手动点「立即同步群消息」看回执 |
| 卡片发到群但内容截断 | 报告超过卡片上限（约 3200 字）会自动截断并提示，完整版在 Reins 看板里 |

集成页底部有**推送日志**（最近 30 条，含成功/失败与通道），排查时先看这里。

## 七、对接实现（开发者）

```
services/feishu.ts         协议层：token 缓存 / 卡片构造 / 加签 / 发消息 / 拉群消息 / 指令解析（零依赖，可单测）
services/feishu-bridge.ts  接线层：设置读取 / 推送队列 / 失败降级 / 入站轮询 / 回执 / Webhook 协议适配
main.ts                    IPC：reins:feishu:{notify,report,test,status,sync,reset}；settings:set 后热重载
preload.ts                 contextBridge 暴露 feishu*，并提供 onFeishuCall（主进程反向调用渲染层）
web/assets/app.ts          集成页表单 / 事件接线 / handleFeishuCall（群指令在渲染层执行）/ buildDigest
test/feishu.test.ts        148 条断言：加签、卡片、token 缓存、重试、去重、水位、加密、调度类型
```

几个容易踩的协议点（已在代码里处理）：

- **加签**：`sign = base64(HMAC-SHA256(key = timestamp + "\n" + secret, data = ""))`，注意是「字符串当密钥、空内容当消息」；带签名的请求体里 `timestamp` 与 `sign` 必须同一层，且签名覆盖除 `sign` 外的完整报文
- **拉历史消息**：`start_time` / `end_time` 是**秒级**时间戳，`container_id_type=chat`
- **卡片正文**：`lark_md` 不渲染 `#` 标题和表格，推送前会降级成加粗行（`textCard`）
- **token 有效期**：缓存到过期前 5 分钟；遇到 `99991663` 等失效码自动换新重试一次，权限类错误不重试
