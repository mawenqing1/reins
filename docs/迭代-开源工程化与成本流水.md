## 一、开源工程配套

### 1.1 CI（`.github/workflows/ci.yml`）

push/PR 触发，两个门：`node --check` 全部入口 JS（渲染层 app.js 无构建步骤，语法错误靠这里兜底）+ `node test/run.js` 全量回归。测试零依赖纯 Node（16+ 兼容），CI 无需 `npm install`，跑在 ubuntu + Node 20。

### 1.2 CSP（纵深防御）

- 渲染层经审查**零远程加载**（无 fetch/XHR/Image 外链，所有网络在主进程）→ `connect-src 'none'` 可以直接关死
- `web/app.html`：`default-src 'self'; script-src 'self' 'unsafe-inline'; connect-src 'none'; object-src 'none' …`——`unsafe-inline` 仅为既有内联 onclick/style 放行，远程脚本/回连一律拒绝
- `web/index.html`（落地页）同口径
- 前置条件 `contextIsolation: true` + `nodeIntegration: false` 本就正确；CSP 补上的是「201 处 esc() 漏一处也不再是 XSS」的那层网

### 1.3 文档与模板

CHANGELOG.md（Keep a Changelog 格式，1.0.0 首发清单 + 1.1.0 本轮）、CONTRIBUTING.md（含「改主进程必须重启再测」等本仓库特有约定）、Issue 模板（缺陷/功能建议）。版本号 1.0.0 → **1.1.0**。

## 二、执行流水表 + Agent 首过率

上一轮遗留清单原话：「没存逐次明细，无法拆出今天花了多少」「无法区分首次即成与返工后成功」。本轮一起做掉——两者共用同一份数据。

### 2.1 纯函数模块 `web/assets/execlog.js`（UMD，浏览器/单测双端）

`makeEntry / push（封顶 500）/ sumDay / recent / firstPassRate / splitUsage / dayOf`。流水挂组织（`org.execLog`），与 agents 同维度。

### 2.2 记账路径统一（`app.js` accountRun）

- **单任务 done / 失败 / 演示引擎交付**：原有路径补 `taskId/taskKey/delivery/firstPass`
- **流水线阶段执行**：**新接入记账**——此前流水线阶段只累 tokens，Agent 成功率/成本/流水表全部漏计；归属按 run 实例携带的 `agentId`（并行阶段 `t.assignee` 会被最后派发者覆盖，不能用它——顺带修掉了 REINS-128 已知边界 C.2）
- **超时收尾按完成推进**的路径（partial 长产出）同样记账
- 计价回包异步回填流水行 `cost/priced`；无用量（演示引擎）标「未定价」而非永久「计价中」

### 2.3 首过率口径

打回计数 `task.rejections`（客户端与飞书指令都走 taskflow 同一计划）；交付级完成时 `firstPass = rejections === 0`；Agent 卡片显示「首过率 N%」（一次通过 M / 全部交付 K，返工后成功计入分母）。

### 2.4 概览

成本条新增「**今日 ¥X · N 次**（+计价中/未定价如实标注）」；新增「**最近执行**」明细面板（倒序 12 条：时间/任务·阶段/Agent·模型/结果/耗时/tokens/花费）。

## 三、云端 SSE 断流自动重连

上一轮设计决策 B.4「断流不自动重试」的前提变了：给节点事件加了序号，续读可以精确去重，就不再需要用户手动重跑。

### 3.1 服务端（`reins-node/server.js`，version 1.1.0）

每个事件带递增 `seq`（run 级）；SSE 本就整段回放缓冲 + 实时推送，天然支持续读。

### 3.2 客户端（`services/runner.js` runCloudTask）

- 事件流循环重构为**重连循环**：流中断（连接被关/读取失败/断流看门狗）→ 自动重连（默认 2 次，`http.resume` 可配，0 = 关闭）→ 回放按 `lastSeq` 去重；**旧节点（无 seq）按「已消费条数」跳过回放前缀**兼容
- 每次连接独立 AbortController：断流只作废本次连接，用户取消经外部信号传播进来，两者在 catch 里可区分（取消绝不重连）
- 重连留 note 痕迹（`[云端] …自动重连续读（第 n/2 次）…`）；用尽才如实报「任务可能仍在节点上执行」
- 新增 `gone` 事件处理：节点已清掉 run 记录（结束后 120s）时明确说「无法续读」

### 3.3 测试坑（值得记录）

第一版测试用**缓冲式** fetch 桩：断流落在建连阶段（响应头都没到），被共享重试层内部重连消化掉了——任务照样完成、去重照样正确，但走不到消费端重连的 note 路径。新增**真流式** fetch 桩（http 模块直通、数据块增量投递）+ 服务端**延迟 destroy**（先送达数据再断）才精确驱动到目标路径。这条经验写进了测试注释。

## 四、调度空间定向（上一轮遗留 C.1）

- 调度项新增 `orgId/spaceId`（`services/scheduler.js` 只透传不感知组织结构）；表单「报告写入空间」下拉平铺所有组织 × 空间，缺省「跟随当前空间」（原行为）
- 三个报告生成器参数化：`buildStandup(sp) / buildWeekly(sp, org) / buildDigest(sp, org)`——按定向空间聚合，不再隐式用当前空间
- 触发时 `schedResolveSpace` 解析；**定向空间已不存在时回落当前空间并在 toast 里如实说明**（不静默写错地方）
- 调度列表行显示「写入 组织/空间」

## 五、小件

- **PAT 探活**（上一轮遗留 D.1）：`services/git-remote.js testToken`——GitHub `/user`（Authorization 头）/ Gitee v5 `/user`（access_token 查询参数，与建 PR 同口径）；设置页「测试 GitHub / Gitee」按钮，未保存的输入框内容也能先验
- **归档正文清理**（上一轮遗留 3）：textstore 新增 `purgeRef`（引用降级 `purged:true` 只留摘要）；integrity 对 purged 引用**豁免缺失判定、不计占用**（有意降级 ≠ 数据丢失）；设置 → 数据自检 →「清理已归档任务正文…」（确认弹窗含任务数/体积/不可恢复警示，建议先导出备份）；只动 `done` 任务——进行中/待验收的正文打回重跑还要用全文。`reins:text:purge` IPC 走同 read 的路径安全校验
- **检查更新**：`services/update.js` 查 GitHub Releases（语义化版本比较，容错 v 前缀/预发布号；解析失败宁可漏报不误报打扰）→ 菜单「帮助 → 检查更新…」→ 有新版一键直达下载页。**有意不接 electron-updater**：应用未签名，macOS 自更新本就走不通；「检查 + 引导下载」在三个平台都真实可用

## 六、状态机收敛第一步（架构债 #5）

`web/assets/taskflow.js`（UMD 纯函数）：approve / reject / revoke 三条迁移的**判定 + 字段变更计划 + 流水线重置口径**收敛为单一来源。客户端（mergeTask/doReject）与飞书群指令（handleFeishuCall）都改为消费同一份计划，各自保留留痕/通知机制。
